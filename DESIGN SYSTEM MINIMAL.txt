# LUMEN Design System — Universal AI Agent Specification (v3.0)

> **Purpose:** LUMEN is an instrument-grade, WCAG AA+, BiDi-native, framework-agnostic UI design system. It gives AI coding agents deterministic tokens, layouts, component specifications, accessibility contracts, and production CSS to build calm, cohesive interfaces for **any** web application (SaaS dashboards, admin consoles, CRMs, developer tools, editors, e-commerce backends, or AI copilots).

---

## 0. AI Agent Operating Contract (Read First)

Before writing any UI code, follow these non-negotiable rules:

1. **Zero Magic Values:** Never use raw hex colors, arbitrary `z-index` integers, or hardcoded border radii inside components. Always reference semantic or component tokens (`--bg-surface`, `--text-muted`, `--z-modal`, `--radius-md`).
2. **6-State Completeness:** Every interactive component MUST support **Default, Hover, Active, Focus-Visible, Disabled, and Loading** states. Every data view MUST handle **Loading (Skeleton), Populated, Empty, Error (with Retry), and Offline/Stale** states.
3. **100% Logical CSS:** Use `inline` / `block` properties (`padding-inline`, `margin-block`, `border-inline-start`, `inset-inline-end`, `border-end-end-radius`, `text-align: start/end`) instead of physical `left` / `right` so LTR and RTL layouts work automatically.
4. **Touch & Mobile Safety:** Use `100dvh` (never `100vh`), apply `env(safe-area-inset-*)` to sticky docks/sheets, step inputs up to `16px` (`1rem`) on touch viewports to prevent iOS Safari zoom, wrap hover effects in `@media (hover: hover)`, and enforce `≥ 42–44px` tap targets on coarse pointers.
5. **Semantic HTML First:** Use `<button>`, `<a href>`, `<input>`, `<label>`, `<dialog>`/`role="dialog"`, and `<table>` properly. Never use clickable `<div>` or `<span>` elements for actions.
6. **Verify Before Finishing:** Run through the **Section 9 Verification Gate** before declaring any UI task complete.

### LLM Anti-Pattern Blacklist (NEVER DO)
* **NEVER** write `transition: all` (causes layout thrashing). Always animate explicit GPU/paint properties (`color, background-color, border-color, box-shadow, opacity, transform`).
* **NEVER** remove focus outlines (`outline: none`) without providing a high-contrast `:focus-visible` ring.
* **NEVER** use OS emojis (`🗑️`, `⚙️`, `📊`) for core UI chrome, buttons, or navigation. Always use crisp `currentColor` stroke SVGs.
* **NEVER** rely on placeholder text as a replacement for a visible `<label>`.
* **NEVER** render default purple/neon gradients, heavy drop shadows, or unrequested decorative glassmorphism on content cards.
* **NEVER** auto-dismiss error toasts before the user can read or act on them.
* **NEVER** place white text on bright green (`#16a34a`) or amber (`#d97706`) buttons (fails 4.5:1 WCAG contrast).

## 1. Visual Philosophy & Customization Slots

| # | Principle | Practice |
|---|---|---|
| 1 | **Calm Neutrality** | Cool zinc surfaces, `1px` hairline borders, whisper shadows. Color signals status or intent, never decoration. |
| 2 | **Disciplined Single Accent** | One brand accent drives primary CTAs, active selections, and focus rings. Primary CTAs use **Hover-to-Ink** (shifting to high-contrast ink on hover). |
| 3 | **Compact, Never Cramped** | `14px` readable body, `rem` scale, 4px spatial rhythm, and `tabular-nums` give dense UIs clarity without bloat. |
| 4 | **Motion as Confirmation** | `150–200ms` snappy deceleration curves, `≤ 6px` travel, zero bounce, strictly gated by `prefers-reduced-motion`. |
| 5 | **Risk-Calibrated Safety** | Low-risk reversible actions execute optimistically + *Undo toast*. Irreversible or bulk destructive actions require **Two-Step Preview → Confirm**. |
| 6 | **Progressive Disclosure** | Keep default views uncluttered; reveal secondary filters, inspectors, and bulk actions contextually. |

### Brand Accent & Density Customization Slots
By default, LUMEN uses **Brand Blue** (`#2563eb` light / `#3b82f6` dark) and **Comfortable** spacing (`36px` default controls). If the target application specifies a different brand color or denser enterprise layout:

* **Custom Brand Accent:** Override `--accent`, `--accent-text`, `--accent-hover`, `--btn-primary-bg`, and derive soft tints safely via `color-mix()`:
  ```css
  :root[data-brand="custom"] {
    --accent: #0f766e;       /* Must pass ≥ 4.5:1 with white text if used on buttons */
    --accent-text: #115e59;  /* ≥ 4.5:1 on both white & --accent-soft */
    --accent-hover: #115e59;
    --accent-soft: color-mix(in srgb, var(--accent) 8%, var(--bg-surface));
    --accent-border: color-mix(in srgb, var(--accent) 26%, var(--bg-surface));
    --accent-ring: color-mix(in srgb, var(--accent) 24%, transparent);
    --btn-primary-bg: var(--accent);
  }
  ```
* **Compact Density Mode (`[data-density="compact"]`):** For data-heavy IDEs, trading desks, or dense admin tables, toggle `data-density="compact"` on `<html>` or a container to reduce control height (`36px → 30px`) and card padding (`16px → 12px`) on desktop while preserving `42–44px` minimums on touch devices.

### 3.3 Formatting, Overflow & BiDi Rules
* **Mobile Input Zoom Guard:** On `@media (pointer: coarse), (max-width: 768px)`, `<input>`, `<select>`, and `<textarea>` automatically scale to **`1rem` (16px)** so iOS Safari never auto-zooms on focus.
* **Tabular Numerals:** Apply `.tnum` (`font-variant-numeric: tabular-nums; font-feature-settings: "tnum" 1;`) to all prices, metrics, timestamps, durations, pagination counters, and table numeric columns.
* **Overflow & Truncation:** Use single-line `overflow: hidden; text-overflow: ellipsis; white-space: nowrap;` only when full text is accessible via hover tooltip, click expansion, or detail view. Never truncate primary action buttons or error messages.
* **Universal BiDi Isolation:** Whenever embedding signed numbers, IDs, SKUs, emails, URLs, or percentages inside potentially RTL sentences, wrap **only** the directional token in `<bdi dir="ltr">` — leave surrounding words/units in document flow:
  ```html
  <span>Balance: <bdi dir="ltr">-1,240.50</bdi> USD · Order <bdi dir="ltr">#ORD-4821</bdi></span>
  ```
* **BiDi Icon Mirroring:** Add `.icon-directional` (`transform: scaleX(-1)` under `[dir="rtl"]`) to directional arrows, chevrons, reply, and sidebar collapse icons. Never mirror checkmarks, plus/minus, search, clocks, or charts.

## 4. Spacing, Shape, Elevation, Motion & Z-Index

### 4.1 4px Spacing Scale (`rem`)
`2px` (`0.125rem`) · `4px` (`0.25rem`) · `6px` (`0.375rem`) · `8px` (`0.5rem`) · `12px` (`0.75rem`) · `16px` (`1rem`) · `20px` (`1.25rem`) · `24px` (`1.5rem`) · `32px` (`2rem`) · `40px` (`2.5rem`)

### 4.2 Shape & Concentric Radius Rule
Always enforce `R_inner ≤ R_outer - padding` so nested borders never look pinched:
* `--radius-xs`: `6px` — Badges, checkboxes, dropdown menu items, small icon buttons
* `--radius-sm`: `9px` — Inputs, buttons, nested callouts, table wrappers
* `--radius-md`: `14px` — Cards, dialogs, dropdown trays
* `--radius-lg`: `20px` — Bottom sheets, floating docks, large showcase panels
* `--radius-full`: `9999px` — Pill tabs, chips, switches, avatars, status pills

### 4.3 Elevation & Dark-Mode Surface Stepping
* **Light Mode:** Borders do the primary structural work; shadows stay restrained (`--shadow-sm` on cards, `--shadow-lg` on modals/toasts).
* **Dark Mode:** Shadows darken, floating surfaces step up to `--bg-elevated`, and overlays add `--highlight-inset` (`inset 0 1px 0 rgba(255,255,255,.05)`) to separate stacked panels cleanly.

### 4.4 Motion & User Preferences
* `--ease-standard`: `cubic-bezier(0.2, 0, 0, 1)` | `--ease-spring`: `cubic-bezier(0.16, 1, 0.3, 1)`
* `--dur-fast`: `150ms` (color, border, opacity, button press) | `--dur-enter`: `200ms` (dialogs, drawers, toasts)
* **Strict Guards:**
  1. Never write `transition: all`.
  2. Wrap hover transitions/styles inside `@media (hover: hover)` so touch taps don't stick.
  3. `@media (prefers-reduced-motion: reduce)` collapses animation/transition durations to `0.01ms`.
  4. `@media (prefers-reduced-transparency: reduce)` replaces `backdrop-filter` glass headers with solid `var(--bg-surface)`.

### 4.5 Canonical Z-Index Scale

| Token | Value | Layer |
|---|---|---|
| `--z-base` | `0` | Page flow |
| `--z-sticky` | `10` | Sticky table headers, sticky section banners |
| `--z-header` | `30` | Sticky top bar / navigation header |
| `--z-dock` | `35` | Bottom action docks, mobile tab bar, chat composer |

## 5. Layout System & App Shell Archetypes

### 5.1 Breakpoints & Container Queries
* `≤ 420px` (`xs`): Collapse secondary header button text to icon-only (with `aria-label`); simplify pagination to `Prev · 2/9 · Next`; 1-col KPI grid.
* `≤ 768px` (`sm`): Tables adapt to cards (or horizontal sticky-column table); modals morph into bottom sheets; 4-col grids drop to 2-col; mobile nav bar / FAB appears; inputs scale to `16px`.
* `> 768px` (`md+`): Full desktop layout (`max-width: 1200px` for dashboards, `760px` for focused views).
* **Container Queries:** Use `container-type: inline-size` inside reusable widgets (KPI cards, detail panels) so components adapt cleanly whether placed inside a narrow sidebar or a wide main grid.

## 6. Universal Component Specifications & Interaction Contracts

### 6.1 Buttons & FAB
* **Heights:** `sm` (`28px` / `36px` touch) · `md` (`36px` / `42px` touch) · `lg` (`42px` / `46px` touch) · `icon` (`34×34px` / `44×44px` touch).
* **Variants:**
  * `primary` (`--btn-primary-bg`, Hover-to-Ink `--btn-primary-hover-bg`) — max 1 per section/dialog footer.
  * `secondary` (`--bg-surface`, `--border-default`) — cancel, secondary actions.
  * `ghost` (transparent → `--bg-subtle` hover) — toolbar icons, table row triggers.
  * `danger` (`--danger-solid` `#e11d48`) — confirmed destructive action only.
  * `danger-subtle` (`--danger-bg`, `--danger-text`, `--danger-border`) — inline row/card delete triggers.
* **Loading State:** Replace or prepend label with a `14px` spinner, set `aria-busy="true"` and `disabled`, and preserve button min-width so layout never shifts.

### 6.2 Complete Form Controls & Validation Rules
* **Visible Labels Always:** Position label (`0.8125rem / 600`) `6px` above control. Mark optional fields subtly `(Optional)` rather than cluttering every field.
* **Validation Timing:** Validate on `blur` or `submit` (never scream red on the first keystroke); clear error immediately once the user corrects the input. Set `aria-invalid="true"` + `aria-describedby` pointing to inline `--danger-text` error text explaining *why* and *how to fix*.
* **Read-Only vs Disabled:** Read-only inputs use `--bg-subtle` with selectable text (`user-select: text`) for copyable tokens/IDs. Disabled controls reduce opacity (`0.45`) and forbid interaction.
* **Boolean & Choice Controls:**
  * **Checkbox (`18×18px`):** Supports `checked` and `indeterminate` (bulk selection). Minimum `36–44px` clickable label row.
  * **Radio (`18×18px` circle):** Mutually exclusive small sets (`2–5` options) when all options should stay visible.
  * **Switch (`38×22px`):** Instant boolean toggles that take effect immediately without needing a "Save" button.
  * **Segmented Control vs Tabs:** Use **Segmented Control** (`.lumen-segmented`) for view switches or binary/ternary modes (`Day / Week / Month`, `Table / Board`). Use **Underlined Tabs** (`.lumen-tabs`) for switching full sub-pages or document sections.
* **IME-Safe Tag / Multi-Value Input:**
  * Ignore `Enter` or `,` while `event.isComposing === true` (protects CJK/Arabic/voice IME composition).
  * **Two-Step Backspace Delete:** Pressing `Backspace` in an empty input highlights the last removable tag (`data-pending-delete="true"`); a second `Backspace` deletes it. Every removable tag has an explicit SVG `×` button (`aria-label="Remove {tag}"`).

### 6.3 Navigation, Overflow & Command Palette
* **Sticky Glass Header:** `52px` (`48px` mobile), `backdrop-filter: blur(16px)`, `1px solid var(--border-subtle)`.
* **Overflowing Pill/Filter Bars:** Apply subtle horizontal edge fade masks (`12px` linear gradient) whenever scrollable horizontally so off-screen items never look mysteriously cut off.
* **Command Palette (`⌘K` / `Ctrl+K`):** For apps with `≥ 6` routes or frequent entity lookups, provide a centered `540px` search modal (`top: 15vh`) with keyboard arrow selection, grouped sections, and `<kbd>` hints.

### 6.4 Data Tables, Cards, Pagination & Skeletons
* **Desktop Table:** Sticky header (`--bg-subtle`, `0.75rem / 600`, `--text-muted`), sortable headers with `aria-sort` + SVG chevron, numeric columns `text-align: end; font-variant-numeric: tabular-nums;`, hairline `--border-subtle` dividers.
* **Mobile (`≤ 768px`) Dual Strategy:**
  * *Mode 1 — Card Stack (Default for feeds, users, tasks, orders):* Collapses rows into clean stacked cards (Primary title ↔ Primary metric/status → Optional `border-inline-start: 3px solid var(--accent)` note → Metadata + Tags).
  * *Mode 2 — Sticky-Column Scroll (When side-by-side column comparison is mandatory):* `.lumen-table-scroll` pins the first identifier column (`position: sticky; inset-inline-start: 0;`) with horizontal overflow scrolling.
* **Responsive Pagination:** Desktop shows range summary (`21–40 of 184`) + windowed pages (`±1` around active + first/last). Mobile (`≤ 520px`) collapses to `[Prev]  3 / 10  [Next]`.
* **Skeletons:** Match exact row/card dimensions with subtle `--bg-subtle` → `--bg-muted` shimmer (`1.4s`) to prevent Cumulative Layout Shift (CLS).

### 6.5 Overlays, Feedback & Resilience Flows
* **Modals → Responsive Mobile Bottom Sheets:** Centered `380px` (compact) / `480px` (default) / `780px` (wide) dialog on desktop; docks flush to bottom edge as a drag-handle sheet (`max-height: 90dvh`, `safe-area-inset-bottom`) on `≤ 768px`.
* **Risk-Calibrated Safety Spectrum:**
  * *Tier 1 (Low-risk / Reversible: archive, mute, remove tag):* Apply optimistically immediately → show Toast with `[Undo]`.
  * *Tier 2 (Irreversible / Bulk / Billing / Permissions):* Render an inline or modal **Two-Step Preview Card** listing exact affected items/counts + `[Confirm {Action}]` danger CTA before mutating data.
* **Toasts (Non-Colliding & Timing Accessible):**
  * Anchored `inset-block-end: calc(var(--dock-offset, 0px) + 16px + env(safe-area-inset-bottom)); inset-inline-end: 16px;` (full-width centered at bottom on `≤ 640px`).
  * Info/Success auto-dismiss after `4500ms` (`7000ms` if carrying an `[Undo]` action) and **pause timer on hover or focus**.
  * Error/Critical toasts **persist until dismissed** (`role="alert"`).
* **Long-Running / Streaming Step Loader:** If an async process exceeds `10s`, reveal calm fallback copy (`"Still working — taking longer than usual…"`) plus a `[Cancel]` affordance so users never assume the app froze.
* **Exports:** Export actions apply active workspace/filters, name files `{scope}-{YYYY-MM-DD}.csv`, and prepend UTF-8 BOM (`\uFEFF`) so international text opens cleanly in spreadsheet apps.

### 6.6 Mandatory ARIA & Keyboard Contract

| Component | Required Semantics & ARIA | Required Keyboard Behavior |
|---|---|---|
| **Icon-Only Button** | `aria-label` describing action | `Enter` / `Space` activates |
| **Switch** | `role="switch"`, `aria-checked="true\|false"` | `Space` / `Enter` toggles |
| **Tabs / Segmented** | `role="tablist"` + `role="tab"` (`aria-selected`) + `role="tabpanel"` | `ArrowLeft` / `ArrowRight` moves selection; `Home` / `End` jumps |
| **Modal / Bottom Sheet** | `role="dialog"`, `aria-modal="true"`, `aria-labelledby` | Focus trapped inside; `Esc` closes (unless dirty guard triggers); returns focus to trigger |
| **Dropdown Menu** | Trigger `aria-expanded` + `aria-haspopup="menu"`; list `role="menu"` / `menuitem` | `ArrowDown` / `ArrowUp` cycles; `Esc` closes and refocuses trigger |
| **Sortable Table** | `<th aria-sort="ascending\|descending\|none">` with interactive `<button>` inside `<th>` | `Enter` / `Space` cycles sort direction |
| **Toast** | Polite info: `role="status"` (`aria-live="polite"`); Errors: `role="alert"` | Pausable on `:focus-within`; close button reachable via `Tab` |
| **Inline Form Error** | Input `aria-invalid="true"` + `aria-describedby="{errId}"` | Focus first invalid input on failed submit |

## 8. Tailwind CSS Integration Guide (For React / Next / Vue / Vite Agents)

If the project uses **Tailwind CSS**, DO NOT fall back to default `slate-*`/`gray-*` hex classes or arbitrary shadows. Wire LUMEN tokens into Tailwind so utility classes reflect the exact design system:

* **Tailwind v4 (`@theme` in `globals.css`):**
  ```css
  @theme inline {
    --color-app: var(--bg-app);
    --color-surface: var(--bg-surface);
    --color-elevated: var(--bg-elevated);
    --color-subtle: var(--bg-subtle);
    --color-muted-bg: var(--bg-muted);
    --color-border: var(--border-default);
    --color-border-subtle: var(--border-subtle);
    --color-ink: var(--text-primary);
    --color-ink-secondary: var(--text-secondary);
    --color-ink-muted: var(--text-muted);
    --color-accent: var(--accent);
    --color-accent-text: var(--accent-text);
    --color-accent-soft: var(--accent-soft);
    --color-danger: var(--danger-solid);
    --color-danger-text: var(--danger-text);
    --color-danger-bg: var(--danger-bg);
    --radius-sm: var(--radius-sm);
    --radius-md: var(--radius-md);
    --radius-lg: var(--radius-lg);
  }
  ```
* **Mandatory Tailwind Utility Conventions:**
  * Use logical classes only: `ps-*`, `pe-*`, `ms-*`, `me-*`, `text-start`, `text-end`, `rounded-ee-sm` (never `pl-`, `pr-`, `ml-`, `mr-`, `text-left`, `text-right`).
  * Use `min-h-dvh` (never `min-h-screen` if `100vh`).
  * Use `transition-colors duration-150` or `transition-[transform,opacity] duration-150` (never `transition-all`).
  * Inputs must include `text-base md:text-sm` (`16px` mobile → `14px` desktop) to avoid iOS Safari auto-zoom.

## 9. Pre-Delivery AI Agent Verification Gate

Before marking any UI implementation complete, confirm every item below:

1. **Token Purity:** Zero raw hex values, magic `z-index` numbers, or `transition: all` in component styles.
2. **Dark & Light Parity:** Tested in both themes; `-text` tokens used for badge/alert text; elevated overlays remain distinct from `--bg-app`.
3. **Complete States:** Loading skeletons, empty states with 1 clear CTA, inline error states with Retry, and disabled/read-only behaviors implemented.
4. **Keyboard & Focus:** Every interactive element reachable via `Tab`, shows visible `:focus-visible` ring, `Esc` closes overlays, focus traps inside modals.
5. **Touch & Mobile (`360px`):** No horizontal overflow, `16px` input font size on mobile, `≥ 42–44px` tap areas, modals adapt into bottom sheets with `safe-area-inset-bottom`.
6. **Logical BiDi Safety:** Layout and bubbles mirror cleanly under `dir="rtl"`, signed numbers/IDs isolated with `<bdi dir="ltr">`, `.icon-directional` SVGs mirrored.
7. **Risk-Calibrated Safety:** Reversible actions offer `[Undo]` toasts; destructive/bulk mutations enforce Two-Step Preview → Confirm.
8. **Preferences Honored:** Verified `prefers-reduced-motion`, `prefers-reduced-transparency`, and pause-on-hover/persistent error timing on toasts.
